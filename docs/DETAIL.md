# 鱼乐一下实现细节

这份文档说明插件由哪些部分组成、每个部分为什么这样写，以及验证做到什么程度。第一次读代码可以先看根目录的 `README.md`。

## 一、整体结构

插件是一个 DSH bundle 包，包名 `dsh-fish-happy`，同时声明主机端入口和浏览器端界面：

- `package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`，安装后由 bundle 机制把插件插入 profile。
- `lib/index.js` 是主机端入口。它通过 `ctx.webServer` 注册联机发现、邀请和出牌操作的本地 HTTP 路由，并在卸载时释放 UDP 和 TCP 资源。
- `lib/lan.js` 是主机端联机实现，负责 UDP 发现、TCP 房间、邀请票据、房主权威判定、按座位裁剪快照、电脑托管和结算。
- `lib/rules.js` 由 `tools/sync-rules.mjs` 从 `lib/client.js` 的规则区生成。主机端和浏览器端共用同一份发牌、牌型识别和电脑出牌逻辑，避免两边规则漂移。
- `lib/client.js` 是浏览器端入口，通过 `window.__ModuleLoader__.load` 把模块交给宿主客户端加载器。单机界面、联机界面、样式和槽位注册都在这个文件里。
- `package.json` 的 `dsh.client.platform` 是 `web`，`inject` 声明依赖语言服务、界面渲染器和布局服务。这些声明只用于保证激活顺序，代码本身不 `require` 任何 `@deepseek-ai/dsh-client-*` 包。

## 二、入口和主面板

侧边栏入口和主面板是两个不同的槽位，必须用同一个标识串起来：

- 标识：`PANEL_ID = 'fish-happy'`。
- 侧边栏槽位：`sidebar.panellist`，注册项 `{ name: 'sidebar.panellist', id: PANEL_ID, order: 40, label: () => tr('panel.label') }`。外层壳子负责按钮、提示和选中态，插件只画 16×16 的鱼形图标。
- 主面板槽位：`main`，注册项 `{ name: 'main', key: PANEL_ID }`。布局服务按这个 key 找页面；如果主面板没有注册，点击侧边栏会抛错并保留当前选中态。
- 回会话：从 `ctx.get('layout')` 取布局服务，调用 `selectPanel(null)`。如果宿主版本不接受空值，再退回 `selectPanel('conversation')`。

`apply` 用 `ctx.effect` 注册语言字典、样式标签和两个槽位，并在清理函数里注销。清理时如果当前主面板正停在这里，会先调用 `selectPanel(null)` 回到会话，再注销图标和样式，避免主区域留下空面板。

## 三、页面状态

页面组件 `FishHappyPage` 有四种视图：

- `list`：卡片列表。
- `snake`：贪吃蛇。
- `ddz`：单人斗地主。
- `lan`：局域网联机大厅和牌桌。

切换视图只改组件内部状态，不碰全局路由。离开面板时整个页面组件被布局卸载，单机游戏状态和计时器一起消失，所以再次进入时总是回到卡片列表，也不会在后台继续跑。联机房间由主机进程维护，是唯一的例外；具体见下一节。

## 四、贪吃蛇

规则区是不依赖 React 和浏览器的纯函数，状态形状是：

```text
{ body, dir, pending, food, score, status, speed }
```

- 初始蛇身三个格子，位于棋盘中间偏左，向右，速度一百八十毫秒走一格。头部到右墙有十二格，给玩家留出反应时间。
- 吃到食物加十分，速度减四毫秒，最低七十五毫秒。
- 撞墙、撞自己结束；棋盘占满时状态是 `won`。
- 反方向输入会被忽略；待执行方向最多缓存两个，避免快速连按造成蛇身折返。

界面每帧用 `setTimeout` 调一次 `stepSnake`，只有 `status === 'running'` 时才安排下一帧。暂停、结束、组件卸载都会取消计时器。页面被切到后台时监听 `visibilitychange` 自动暂停。

canvas 每次绘制都从 `getComputedStyle(canvas)` 读取主题变量，再用 `ResizeObserver` 和 `MutationObserver` 在尺寸或主题变化时重画。这样不需要维护两套颜色，也不会写死某个主题的色值。

最高分保存在浏览器本地的 `dsh-fish-happy:snake-best`。本地存储被禁用时读写都会安静失败，不影响游戏。

## 五、斗地主

### 牌和牌型

一副牌五十四张：三到十五各四门花色，十六是小王，十七是大王。牌型识别函数 `analyze` 支持：

单张、对子、三张、三带一、三带二、顺子、连对、飞机、飞机带单、飞机带对、炸弹、王炸。

比较函数 `beats` 的规则是：同类型、同长度比主点数；炸弹可以压普通牌型；王炸最大。顺子和连对不允许包含二和王。

### 对局流程

状态形状是：

```text
{ phase, hands, bottom, landlord, turn, lastPlay, actions, winner, notice, seq, multiplier }
```

- 进入斗地主后先显示准备页。点「开始游戏」才发牌，九张牌背面依次展开，一千三百毫秒后进入 `bid` 阶段。这一步保证用户看清发牌，不会一进页面就发现牌已经发好、倒计时在走。
- 人类固定在零号座位，一号和二号是电脑。
- 发牌后进入 `bid` 阶段，人类先决定叫不叫。人类不叫时，两名电脑按手牌强度依次决定；三个人都不叫就重新发牌。
- 地主拿到底牌并先出牌。
- 出牌后轮到下一家。两家都不要时，桌面清空，由上一手牌的主人重新自由出牌。
- 任意一家手牌出完，`phase` 变成 `over`，记录赢家。
- 每次打出炸弹或王炸，倍数翻一倍，最高十六倍。结算时按底注乘倍数计算欢乐豆。

电脑策略刻意做得简单：农民不压队友的牌；能一次出完就一次出完；否则优先出小单张、对子或者顺子，炸弹留到对手快出完或者自己牌很少时才用。它不追求强度，只保证合法、能正常结束。

### 界面和计时器

- 电脑轮到时延迟七百二十毫秒再走，让用户看清桌面变化。
- 每次状态更新都会增加 `seq`，effect 依赖 `phase / turn / seq`，并在清理函数里取消计时器。
- 人类出牌前会先用 `analyze` 和 `beats` 校验，不合法就显示提示，不会把非法牌型写进状态。
- 叫地主有十五秒、出牌有三十秒读秒，最后五秒倒计时变成红色。超时后叫地主自动不叫；跟牌自动不出；轮到自己自由出牌时用 `chooseLead` 打出一手最小的牌。
- 倒计时剩五秒且人类还没选牌时，界面用 `findBeats` 或 `chooseLead` 自动选好推荐牌，并显示“时间快到了，已按提示选好，点出牌确认”。如果找不到能压过的牌，就清空选择并提示“要不起”，同时把「不出」按钮高亮。
- 「托管」开启后，轮到人类时延迟七百六十毫秒自动叫牌或出牌；手动点牌、出牌、不出或按提示会取消托管。托管按钮带 `aria-pressed`，座位旁显示“托管中”。
- 欢乐豆保存在 `dsh-fish-happy:ddz-beans`。开局底注五百，地主的输赢是底注乘倍数的两倍，农民是一倍；每次结算后三家余额一起更新，人类余额写回本地存储。余额低于五百时，点开始会补一千救济金。
- 桌面每走一手牌就清空当前选牌。否则上一轮选中的牌会留到下一次轮到自己，再按出牌就会看到已经过时的“压不过”提示。
- 手牌支持点按选中，也支持按住鼠标横向拖过连续的一段牌；拖动始终从按下时的选牌状态重新计算整段，所以鼠标拖回来时能恢复原样。
- 电脑作为农民不压队友的牌时，座位旁显示“队友的牌，不压”，避免用户把主动让牌看成漏出牌。每家的出牌都显示在各自座位下方，自己的出牌显示在手牌上方的横条里，不再把三家出牌堆到桌面中央；这样上家、上上家分别出过什么牌，都能按座位对上。
- 手牌按钮带 `aria-pressed`，桌面上不可点击的牌渲染成普通 `span`，避免误触。

## 六、局域网联机

联机部分分成主机进程和浏览器界面两层。主机进程只负责网络和权威状态，浏览器只负责显示和上传操作意图；这样页面切走以后牌局还能继续，也不会让每个客户端各自算一套牌。

### 发现和邀请

- 联机开关默认关闭。用户在联机页点「开启联机」后，主机进程才创建 UDP socket，并向 `239.255.42.99:45873` 组播、同时向广播地址发送 `fh-presence` 心跳，每三秒一次。超过十二秒没有心跳的同事会从列表里移除。
- 心跳里带随机实例标识、昵称、主机名、协议版本、在线状态和发现端口。实例标识每次启动重新生成，避免同一台电脑上两个进程把对方的心跳当成自己的。
- 邀请由房主单播给指定同事，十五秒内有效。对方接受后，房主发一次性票据；客人凭票据通过 TCP 连接房主的房间端口，房主验证房间标识和票据后分配一号或二号座位。
- 同一局最多三名真人：房主自己加两名客人。人不够时，空座位在开始牌局时补成电脑。房主退出房间时，真实客人会收到“房主摸鱼可能被抓住了，风紧撤呼！”。
- 页面通过 `/plugins/dsh-fish-happy/lan/status`、`/invite`、`/reply`、`/start`、`/action`、`/leave` 等本地路由和主机进程通信。路由只接受本机请求，非本机访问返回 403。

### 权威状态

- 房主对叫地主、出牌、不出、托管和超时做最终校验，客人上传的牌必须真的在手里、牌型合法、并且能压过桌面。
- `snapshot(seat)` 按座位裁剪：自己的座位带完整手牌，其他座位只带剩余张数；地主确定前底牌不可见，确定后才公开。
- 房主页面不享受看牌特权：`getStatus()` 里房主的 `room` 也是用 `snapshot(0)` 生成的，只包含房主自己的手牌；联机大厅还专门写了“房主页面也只显示自己的手牌”。房主进程为了校验牌型，内存里确实持有三家手牌，这是“房主权威判定”无法回避的代价；但没有任何路由会把其他座位的手牌发给页面。以后若做“明牌”，应当是玩家主动亮牌，而不是房主默认获得的信息。
- 叫地主和出牌都有截止时间。真人超时后，房主把该座位标记为自动托管，由电脑按当前牌局继续出牌；客人掉线超过宽限期也会进入同样的托管状态。
- 牌局结束后，房主仍保留房间和三家欢乐豆，点「再来一局」可以重新发牌；客人留在房间里等待下一局。

### 界面

- 游戏列表的第三张卡片是「局域网斗地主」。卡片角标写“联机”，不写“单人”。
- `LanLobby` 每秒半轮询一次状态，显示在线同事、邀请、三个座位、开始按钮和离开按钮。房主开始后，大厅换成 `LanTable`。
- 邀请提示注册在 `shell.overlay` 槽位，因此用户停在会话页或单机游戏里也能收到。接受后自动切到「鱼乐一下」的联机页。
- 联机牌桌复用单机的牌面、拖动选牌、倒计时和托管样式，但出牌前先做本地预检，最终仍以房主返回的快照为准。
- 联机牌桌的每个座位都显示该座位最近一手的牌或“不出”，自己的出牌显示在自己手牌上方；中央桌面只保留底牌和轮次提示，不再把三家出牌混在一起。

### 后台例外

单机游戏离开面板就停止；联机房间是例外，房主进程必须继续维护房间和读秒，否则客人会掉线。这是联机功能的必要后台，不会在用户没有开启联机、没有进入房间时运行。

## 七、主题和样式

所有颜色都引用宿主变量：

- 背景：`--dsw-alias-bg-base`
- 表面：`--dsw-alias-bg-layer-1/2`
- 文字：`--dsw-alias-label-primary/secondary/tertiary`
- 强调色：`--dsw-alias-brand-primary`
- 错误：`--dsw-alias-state-error-primary`
- 边框：没有直接使用 `--dsw-alias-border-l1/2`，而是把 `--dsw-alias-label-primary` 按百分之十六和百分之二十六混入透明色。宿主亮色主题的边框色是白色半透明，放在白底上看不见，牌背和卡片轮廓会消失；用文字色混合后，明暗主题下都有可见的描边。

根节点 `--fh-accent` 从品牌色派生，页面背景用品牌色做低透明度渐变。浅色主题下背景是浅色，深色主题下背景是深色，切换主题不需要重新加载插件。

牌背的斜条纹用品牌色和表面色按比例混合，亮色主题下不会淡成一片白，暗色主题下也不会变成刺眼的白块。角色标签和倒计时文字使用品牌色与正文文字色的混合色，小字号在两种主题下都能保持足够的对比度。

斗地主结算遮罩的定位基准是牌桌容器 `.fh-ddz-table`，只模糊牌桌和手牌，不会盖住左侧边栏和顶部工具栏。遮罩里的“再来一局”按钮和结果文字始终显示在牌桌中央。

样式标签带 `data-plugin="dsh-fish-happy"` 和 `data-plugin-css="dsh-fish-happy/game.css"`，重复挂载时复用已有标签。所有选择器都限定在 `.fh-` 类名下，不会影响宿主其他界面。

## 八、语言

界面文字全部走语言服务：

- `apply` 里调用 `locale.register('fish-happy', DICTS)`，再用 `locale.bind('fish-happy')` 得到翻译函数。
- 页面订阅语言服务的 `subscribe`，切换语言后重新渲染。
- 语言服务还没接好时使用兜底翻译，按页面根元素的 `lang` 属性选择中文或英文，不会把内部键名直接显示给用户。

`locale/zh.json` 和 `locale/en.json` 只保存插件列表里的标题和说明，界面文案在 `lib/client.js` 的 `DICTS` 里。

## 九、验证

已经做的验证：

1. 用 `new Function` 解析 `lib/client.js`，确认没有语法错误；用 `node --check lib/lan.js` 检查主机端脚本。
2. `tools/test-rules.mjs` 从模块里取出规则函数，测试牌型识别、大小比较、提示合法性、农民让牌原因、三百局全电脑完整对局，以及贪吃蛇吃食物、撞墙、撞自己、满屏。
3. `tools/test-lan.mjs` 启动两个独立联机实例，验证邀请、票据入座、按座位裁剪手牌、房主退出提示，并额外断言房主快照只有自己的十七张手牌、没有 `hands` 字段、不会出现客人的手牌。
4. `tools/audit-client.mjs` 检查中英文字典键一致、界面用到的键都存在、样式选择器全部限定在 `.fh-` 下。当前中英文字典各一百八十一个键，界面使用一百五十三个，样式选择器二百四十二个。
5. 在真实的 51812 页面里安装了插件，验证了侧边栏入口、卡片列表、贪吃蛇的开始/暂停/转向/撞墙/再来一局，以及斗地主的准备页、点击开始后的发牌页（九张牌在一千三百毫秒内依次展开）、叫地主、提示、拖动选牌、五秒自动荐牌、要不起高亮、托管自动叫牌和出牌、炸弹倍数、整局结算、豆子余额变化、从游戏退回卡片列表、从面板返回会话、明暗主题切换，以及 1100 和 900 像素宽度下的布局。本轮还用无头浏览器确认：电脑甲的出牌显示在甲座位下方，自己的出牌显示在手牌上方，中央不再堆放三家出的牌。
6. 联机部分在 51812 页面用两个假客人进程验证了：开启联机后互相发现、邀请和接受、房主加两名客人入座、三家各十七张牌、房主托管自动打完整局、结算豆子更新、点「再来一局」重新发牌、房主离开后客人看到“房主摸鱼可能被抓住了，风紧撤呼！”。邀请浮层在会话页和单机牌局上方也实际出现过，拒绝后浮层消失。联机大厅的公平性说明也已在页面上确认。
7. 刷新页面后检查宿主控制台，没有插件产生的报错。重开面板时单机游戏状态归零，说明离开面板后单机计时器确实被清理。发牌页曾经因为准备页判断排在前面而永远显示不出来，已改成发牌期间先显示发牌页，并重新用 DOM 轮询确认九张牌确实挂载了一千三百毫秒。

英文界面只做了字典键一致性检查，没有在宿主里实际切换到英文查看显示效果。
